# Expensive FPGA campaign policy

User directive 2026-11-05: maximize useful evidence per hardware setup. Follow AGENTS.md and OPERATING_RULES.md.

1. Prove exclusive ownership and complete occupancy visibility before any destructive action. Use kill -> infrasetup -> runworkload -> kill, including ownership-checked failure cleanup. No direct-driver bypass.
2. Start with one small bring-up smoke. After it passes, bundle many compatible microbenchmarks, shapes, hart subsets, warm/cold cases and repeated trials INSIDE ONE ELF. A bundled run gets one infrasetup, not one per case. Different ELFs remain distinct lifecycle runs until a supported reload path is verified. Preserve fitting versus held-out identities; do not fit on held-out timing data.
3. Measure host time for the kill, transfer, programming/setup, workload and cleanup phases separately where observable. Cache/stage the EXACT image and matching driver near the FPGA only if transfer is material. Verify full hashes on both ends, preserve originals, use private/stable paths, and preserve runtime/hwdb/input receipts. A copied bitstream is not a programmed FPGA; caching never authorizes skipping reset/programming/setup.
4. Freeze a capture checklist BEFORE setup: raw manager/stdout/stderr/UART logs, all guest region mcycle/minstret/checksums and completion markers, active/inactive hart policy, repetitions and variance, actual runtime/HWDB/plusargs, ELF/driver/image/toolchain/source hashes plus dirty patches, loaded-image association and unknowns, and available host/target counters/traces. Preserve failures and timeouts. Avoid overwritten fixed log names by using a unique run directory.
5. Inspect THIS image's instrumentation before launch. Enable supported trace/autocounter windows and function/region attribution where useful; record trace filters, windows, data volume and unavailable instrumentation. Do not silently change clock/memory parameters or claim counters exist because source files do. Guest cycles are distinct from host elapsed time and emulation throughput. Do not use cumulative driver cycles as per-run timing.
6. Prepare local input hashes, independent checksums and capture configuration first. Collect incrementally where possible. After each run (including failures), finish owned cleanup and archive the quiescent job with `python3 firesim/capture_run.py <job> --output <archive-outside-job>.tar.gz`. The archive preserves existing files and raw bytes with SHA256 inventory, skips shared symlinks and records missing context. It does not generate missing measurements or certify a bitstream. If files are still changing, stop capture and preserve the partial archive; use a fresh archive name after quiescence.

Active session owns integration into its runner/campaign plan. All existing 12-region smoke, 54-region baseline and 432-region distribution jobs are preparatory coverage, not completed hardware measurements or the complete identifying/held-out suite.
