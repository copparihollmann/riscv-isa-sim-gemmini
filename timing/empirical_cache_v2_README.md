This successor adds separate instruction-cache timing tags to the experimental data-cache history model. Frozen v1 files and proofs remain unchanged. `CacheHistoryV2(iris_geometry_v2())` retains data `begin`, shared owner `complete`, and adds `begin_instruction` and `fence_i`.

L1I geometry is harts0/1 64sets×2ways×64B=8KiB, hart2 128sets×2ways×64B=16KiB. L1D and shared L2 geometry retain v1. The instruction and data interfaces share the SAME L2 tags, accepted-request ownership, and pending dependencies. A data transaction and instruction refill on one line cannot bypass each other merely because a timing tag was installed early. Instruction requests reject writes.

The source instruction-cache boundary is Get-only and has no coherence B channel. Consequently stores invalidate other private DATA copies, while instruction tags persist until explicit local `fence_i`. L2 evictions invalidate inclusive DATA copies and preserve instruction tags. A cold instruction refill can obtain a modified line from a dirty DATA owner, including the same hart. This models tag/ownership work, not instruction bytes. The functional CPU must retain actual fetch permissions, knownness and owned publication.

`fence_i(hart,tick)` requires that hart's accepted timing requests to have drained; it clears only that hart's instruction tags. It does not flush peer I caches, data caches, L2, backing memory, or other harts' accepted transactions. The caller supplies FENCE.I execution/drain timing. `reset_timing_tags` clears both types only with no pending owners. Construction abstracts empty reset tags and does not model hardware reset/wipe latency.

Only DRAM instruction addresses allocate tags in this first scope. ROM/TCM/scratch addresses retain their real route classification but receive no invented instruction-cache policy or service time. The helper contains no latency constants, measured state, benchmark or PC identities, golden cycles, seeded FPGA INIT, or memory values. Replacement remains explicit LRU and coherence remains a timing approximation. Instruction refill service is an external candidate requiring actual runtime validation; no K1 measurements were used to set it.

The proof replays all60,049 data checks from v1 against the successor and90,023 instruction/data checks, including30,000 mixed three-hart accesses checked by an independent per-cache LRU/dirty-owner oracle. Both optimized and checked standard-library builds run. This is component semantics evidence, not RTL/FPGA timing certification.
