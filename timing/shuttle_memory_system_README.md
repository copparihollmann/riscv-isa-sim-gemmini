# Three-hart source memory component

This successor adds both saved Shuttle memory tiles and guarded L1D caches to the existing Rocket → NoC → L2 → SerialTL → Bringup → FASED boundary. It is a physical component SDK, with explicit caller edges and functional memory service. It does not replace the published functional simulator or claim complete CPU, Zephyr, FPGA-image or calibrated timing qualification.

The SDK is `build/shuttle-memory-system-native-v6/sdk/shuttle_memory_system.hpp`; its build receipt lists the exact static-library order and include paths. `System::evaluate` settles all peers without a clock edge; `sample` returns physical outputs; `commit({rocket,uncore,bringup,serial})` samples the same settled inputs in the selected domains. Qualified source-relative periods remain Rocket=2, uncore=2, Bringup=1, Serial=10. Both Shuttle memory/coherence paths follow the saved synchronous uncore connection, including while a CPU sleeps. A live CPU integrator must settle its producers with these peers before any selected edge.

The new cuts retain the actual ShuttleDCacheArbiter (PTW requestor 0, scalar 1), PTW with all four parent address-pipeline registers, width widgets, tile crossbars, address offsetters, TCM replicators, both SRAM banks, synchronous PRCI buffers and separate SBUS couplers. Source-assigned hart IDs are derived from `BundleBridgeNexus_UInt2_3`, retained internally, and cannot be supplied by a caller. The two NoC slave bindings come from their separate DigitalTop instance connections. CPU/cache/frontend ports are 64 bits; Saturn ATL and tile internal paths are 256 bits; the tile system master is 64 bits. These are physical interface widths, separate from Saturn DLEN.

Default cache replay policy remains `RefuseUse`. An unwritten invalid replay-head command is not assigned a seed-based hardware value. The positive fixture initializes every RPQ slot using 64 accepted loads per Shuttle; this is an explicit functional initialization stimulus, not evidence that normal boot does so. The cold-store negative control must refuse.

TCM contents have no reset value. A sidecar records only byte masks of actually accepted physical Put writes, using the source SRAM row expression `{address[16:7],address[5]}` separately for each bank and hart (TLRAM.sv, memory instance RW0_addr binding). Reads and atomic read-modify-writes require the touched bytes to have been written. Untouched neighbors remain unknown. Reset does not silently erase or define SRAM contents. This checks data definedness at the memory component; inline CPU LSU exception/PMP/PMA logic is outside this cut, so this SDK alone does not qualify TCM LR/SC traps or whole-CPU faults.

The fixture explicitly supplies FASED parameters 30/30/16/16, ideal functional backing and reset-only diagnostic suppression. They are test inputs; the SDK has no latency/service default. The suppression policy affects diagnostic STOP/PRINTF guards only while both external resets are asserted. Default source assertions stay enabled. Runtime host-token, arbitrary host backpressure, image association, complete four-state internal definedness and arbitrary unreset RNG-order invariance remain unqualified.

`build/shuttle-memory-system-check-final-v1` passes 104,802 checks at seeds 1 and 17: independent load values and tags, dirty Shuttle → Shuttle → Rocket → Shuttle ownership, actual B/C probes without extra outer reads, source LR/SC success and failure, AMO-add old-value ordering across Shuttle and Rocket, both TCM banks including the last row, local/alias/peer/Rocket paths, and refusal of an unwritten neighboring byte. Source CPU pipelines are not present in this fixture. Wrong backing data and a cold store are separate failing controls.

`build/shuttle-memory-system-guards-final-v1` passes 1,929 checks, including all 316 unknown external fields, excess value/knownness width, joined-port/ID injection refusal, reset admission, stale phases and repeated evaluate. `build/shuttle-memory-system-context-final-v1` passes 3,447 injected allocation failures over every observed constructor frontier, plus 24 successful constructions, with no target edges. Its parent host derivatives select one host thread, exactly matching the unchanged compiled model's `threads()==1`; all target model/runtime objects remain byte-identical. Historical extraction, source-ID, fixture-tag, missing CPU-retry and inherited worker-pool failures are preserved under earlier build paths.

The component capsule and independent archived-consumer verification are generated by `shuttle_memory_system_accept.py` and `shuttle_memory_system_verify.py`. They retain source, commands, exact SDKs, checks, source-derived mapping and parent closure identities. Full-model availability, ±2% timing, calibration and loaded FPGA image qualification remain false.
