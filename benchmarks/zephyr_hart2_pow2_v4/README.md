This is a NEW functional-first Zephyr SMP campaign on the unchanged Iris kernel overlay. It has no FPGA timing reference yet and is not authorized for calibration merely because cases are training eligible.

The main thread boots on physical/logical hart0, creates one persistent worker pinned to each of harts0/1 and a scalar controller pinned to hart2, then blocks. A controller-ready semaphore runs before first VME ownership; workers acknowledge ownership before dispatch begins. Hart2 prepares inputs, sends sequence-numbered semaphore work, receives matching acknowledgements and independently checks all numeric outputs with integer code. It performs no application RVV or FP operations. Inactive compute workers block on semaphores; this is a Zephyr scheduling policy, not a claim of no interrupts or cache activity. Kernel vector context code is unchanged; migration and multiple VME owners on a hart are outside scope.

The corpus has 486 dispatch groups and 648 active-hart regions: 288 VADD and 360 matrix. RVV uses SEW8/16/32 and LMUL1/2/4/8, giving 32/64/128/256-byte vectors. Matrix uses square 8/16/32 with TK1, unsigned INT8 and E4M3×E4M3, E4M3×E5M2, E5M2×E4M3, E5M2×E5M2. Each geometry has EXACT17 or65 operations, masks1/2/3 and three trials. There is one16-operation loop body plus a final tail operation; the loop iterates1 or4 times. No per-operation C dispatch, helper, memory reload or metadata load occurs in these bodies.

FP8 A's E5 selector is instruction rd[0], B's is vtype.altfmt (bit8). The header's alias macro names alone do not select B's format. This packet emits explicit E4/E5-A words and separately configures the B selector. Signed finite integers exactly representable in both formats produce exact FP32 integer results. The hart2 FP8 encoder and FP32 result packer use integer operations. This is finite all-pair coverage, not arbitrary FP8 special-value/rounding coverage.

The selected body is pre-executed unmeasured. Afterwards every active output and both guards are re-poisoned, inputs/VRF or tile state reset, and a fence completes setup. This is conditioned/reset history, not proof of physical cache hits, cold state or cache flushing. All trials remain present.

The measured interval contains actual MCYCLE/MINSTRET reads, an indirect call, exact target instructions and scalar loop/return overhead, an issue MCYCLE read, FENCE rw,rw and final MCYCLE/MINSTRET reads. Only total interval instret is reported. Output vector stores and supported tile ROW readout happen after this interval. Matrix checks cover every active M×N cell, not unused MRF padding or disabled-column semantics. No IRQ masking or invented service/latency occurs in the app.

All181,440 active elements are checked by C and by an independent Python implementation, with648 before/after output guards. The full679,680 active bytes are retained and emitted in little-endian128-byte hex chunks. Only after all group measurements, stores, acknowledgements and checks does hart2 write count648, fence, clear the file-backed UINT64_MAX completion sentinel, fence, and call noinline `emit`. A debugger may stop at `emit` for controlled postmeasurement readback; that is not normal HTIF/UART completion. Real hardware qualification requires every region/data chunk, exact final footer, all words and normal driver exit0.

Reserved identities are frozen prospectively: RVV LMUL4 (all SEWs/repeats/masks/harts/trials) and matrix shape16 (all formats/repeats/masks/harts/trials), totaling192 regions. No FPGA operation, hardware preparation, source/image association, whole-SoC timing certificate or ±2% claim is included in source qualification. Hardware remains root-coordinator only using all four managed lifecycle phases, current authorization/complete inspection/shared lock, full success/failure capture and original driver.
