# Experimental executed-ELF Shuttle memory integration

The isolated successor is `pipeline/riscv-isa-sim-shuttle-memory`, based on Spike72958551566a30f19444bd7e354552824e4d0a98 plus the exact frozen15b overlay. Primary359, the Saturn agent's tree, and every frozen SDK remain unchanged. `pipeline/build_native_shuttle_memory.py` builds a paired ABI4 native/UART and records actual compiled dependencies. No public simif/VU layout changed.

The new bridge is `riscv/iris_shuttle_memory.cc`; `pipeline/shuttle_serial_peer.{hpp,cpp}` joins the qualified453fad48 three-hart memory System to the unchanged source Rocket frontend/arbiter and fixed-context LP. All original scalar/PTW arbitration, width conversion, coherence, NoC, L2, MBUS, SerialTL and Bringup paths are retained. Global phases remain Rocket/uncore2, Bringup1, Serial10. No measured readiness, source register values or selected delays enter a model.

An explicit fixture line enables `shuttle_scalar_memory source-cache-serialized-M-mode`. The shared-System identity and LP parameters/identities remain mandatory inputs. This profile uses explicit ideal functional AXI backing and a separate synthetic CBUS service; LP30/30/16/16 are test inputs, not admitted hardware defaults. Shuttle instruction-cache service remains the existing explicit synthetic fixture, while Rocket fetch uses the physical hierarchy. This is not all-three-CPU cycle qualification.

The admitted Shuttle subset is32-bit-encoded aligned LD/SD in bare M-mode over DRAM, plus FENCE rw,rw. Load/store operands must be defined. CPU cache tags follow the actual source Cat(rd,fp=0); S1 physical addresses follow accepted EX requests. Ordinary loads publish source response data only under the matching tag/owner. Store publication to Spike's architectural mirror occurs only after the owned source cache response; the independent outer backing changes only at physical AXI writes. HTIF observes the architectural mirror, so exit success does not by itself prove an outer writeback. Narrow/compressed memory, other FENCE forms, atomics, translated/debug privilege, non-DRAM data and unqualified S2-nack replay staging refuse. Broad Shuttle LSU issue overlap, late integer destination forwarding, fault staging, interrupts with general outstanding loads and Zephyr timing remain open.

A serialized-load warmup cannot initialize every RPQ: when no replay queue is valid, the arbiter's bits default to MSHR3 even if only MSHR0 was used. The first real ELF exposed this correctly after64 good loads: the following store refused queue3/slot0. That failure remains preserved. The bridge never selects arbitrary reset values or adds hidden loads.

An independent unchanged56-module ShuttleCore reference proves the narrow exception needed for real warmup: an accepted load request at edge3 retires at COM5 before a response at43; a dependent integer instruction waits until47. A load to x0 also retires at5 and its following independent work proceeds without waiting for data. The reference checks the exact tag, S1 physical phase and dependent store data at seeds1/17. Evidence is `build/shuttle-lsu-phase-check-v2/results.json`; source RTL/tool identity is in `build/shuttle-lsu-phase-source-v1/build.json`. External cache response delay40 is an explicit functional control fixture, not a hardware memory-latency parameter.

Accordingly, only LD-to-x0 may finish its CPU frontdoor actor at accepted EX+2 source edges. Its remaining cache work lives in a per-hart tag0 cohort until actual responses drain. The tag0 interface cannot identify an individual response PC, so no such attribution is invented. A normal load/store cannot cross that pending cohort without the supported fence. FENCE waits for actual cache ordered and zero owned pending responses, followed by the serialized pipeline boundary. This remains a conservative boundary, not a throughput model.

The full positive ELF contains64 actual load-to-x0 instructions (16 requests to each of four lines), a draining fence,64 checksum-checked loads, a store/load check, a final discard/fence and an actual HTIF exit. Both Shuttle workers independently pass at seeds1/17. Each run has134 memory/synchronization transactions. There is no host-injected warmup. The minimal192-byte diagnostic ROM jumps from the real reset address0x10000 to the ELF and is separately hash-bound; it is explicitly not the shipped BootROM. The shipped startup requires32-bit MMIO operations outside this first subset.

Earlier read-only positives exit under an explicit512-instruction diagnostic bound after their checksum/pass loop; they are retained separately and never described as complete HTIF runs. The four later HTIF positives are the actual complete-program tests. Cold store, unknown address, unaligned/narrow/atomic/compressed operations, nonqualified FENCE, missing outer data and queue-pressure NACK have separate negative controls. Ordinary functional32 is replayed with timing disabled, preserving its own existing scope.

This path is slow: the current source-model/fixed-point reference takes about one minute for roughly84k virtual phases in the small positive. Host elapsed time and retired counts are retained; no tuning-speed promise is made. Full±2%, image association, complete internal knownness, all-three-hart contention and full model availability remain false.
