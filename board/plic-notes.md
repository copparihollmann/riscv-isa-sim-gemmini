The Iris PLIC adapter selects the configuration from the elaborated device tree: one device interrupt, six contexts ordered as M/S for harts 0, 1 and 2, maximum priority one, and a 64 MiB aperture at `0x0c000000`. Generic Spike PLIC behavior remains selected when `--iris-bootrom` is absent. The adapter requires the exact three architectural hart IDs and supervisor support on every hart.

The helper follows the pinned Rocket implementation, including behavior that differs from the generic Spike PLIC: priority, enables and thresholds have no reset initializer; a pending interrupt remains latched after the peripheral level drops; claims are global and ignore the context's threshold; completion can come from any enabled context; and completion IDs truncate to the single implemented ID bit. A read of any byte of a claim field fires the read effect, while completion requires all four bytes to be written. Unimplemented aperture locations read zero and ignore writes. See [the source evidence manifest](plic-source-evidence.json), [PLIC RTL](evidence/plic.scala), [RegMapper](plic-evidence/regmapper.scala), and [RegField](plic-evidence/regfield.scala).

Unknown register bits stay unknown until initialized. An unknown interrupt line fails closed when its hart enables that interrupt or reads `mip`. The adapter also checks an enabled unknown immediately when the peripheral changes the line, so a hart parked in WFI cannot silently hide it. It never delivers an unknown as an asserted interrupt. The parent core calls `plic_t::validate_iris_interrupts(hart, read_pending)` through its existing interrupt-observation guard.

Run `python3 board/run_plic_tests.py` for standalone helper checks. `python3 board/plic_integration_check.py --build-only` compiles ordinary ELF regressions without rebuilding Spike; omit `--build-only` after the coordinated native rebuild. The process cases cover unknown MMIO reads, unknown enabled/observed IRQ lines including a hart parked in WFI, external interrupt bits on all three harts, exclusive claims and cross-context completion, machine and supervisor external trap entry/return, and generic-mode compatibility. The runner records exact binary, ELF, compiler, device, ROM, DTB and source digests with stdout/stderr artifacts. The UART is used to create a source-high condition, rather than to certify UART FIFO timing.

PLIC fan-in registers, the registered IRQ output and TileLink transport latency remain uncalibrated. Functional gateway sampling occurs on delivered peripheral level events and the core's scheduled peripheral updates. These checks establish functional adapter coverage; they do not certify RTL cycle accuracy, a complete board or Zephyr SMP boot.
