# First-row service in the selected WS ExecuteController

Selected `ExecuteController.scala` assigns both `performing_single_preload` and `start_inputting_d` in `waiting_for_cmd` (lines585–595); its MUL_PRE and single-multiply branches similarly assign their active operands on that edge (lines600–621). `computing` drives control-queue valid combinationally. Therefore the first row can fire in the command-selection cycle. The compute-state `about_to_fire_all_rows` branches pop the consumed commands on the final row (lines634–677). The row-counter predicate additionally requires a prior started bit, so it cannot falsely finish on the first row.

For distinct active scratchpad banks, no transpose, unit stride and no downstream stall, a DIM16 feed consumes rows0..15 on16 consecutive edges. The following command's first row can fire on the next edge. The previous selected aggregate service added a seventeenth controller cycle. `source_ws_first_row_bypass` removes that unsupported extra cycle for this existing admitted WS domain, with explicit source facts. It preserves the actual16 row-bank reservations, register-read lifetime through the final read response, queue capacities, accumulator port arbitration and the existing nominal mesh result envelope.

The focused ACC dependency test verifies16-cycle successive compute-group starts with this source selector (legacy control17), preserving same-row WAW and independent bank overlap. This is a controller handshake correction; it is not a changed MAC price or a claim that arbitrary transpose/same-bank/mesh-stall cases are supported.
